# 织界实验室：以孩子想法为起点的 PBL 共创计划

- 记录日期：2026-11-03（Asia/Shanghai）
- 状态：讨论共识与首期活动草案；尚未实施或验收。
- 范围：Loom OS、Loom Web / 织界空间、实体动手环境，以及孩子、G 老师和现场家长的协作方式。
- 文档定位：本计划的主记录，先留存在 loom-web；不另建重复系统，不替代两个仓库现有技术规格。
- 授权边界：本次仅留存计划，不授权功能开发、硬件采购、设备控制、音视频采集、发布或部署。

## 1. 已确认的核心方向

主题始终是孩子自己的想法，而不是 Loom 的功能、AI 的能力或成人预设的作品。G 老师和家长都为孩子实现自己的想法提供支持。

首期的起点已经明确：机器狗就是她自己想要的作品，不是成人替她选择的教学题目。后续从“她想要怎样的机器狗”出发细化实现，不重新把“是否想做机器狗”列为待确认问题。

“独立完成”不是要求孩子独自解决所有技术问题，而是保留她对作品目标、关键选择、动手尝试和结果解释的所有权。底层工具可以由成人和 AI 提供，并向孩子说明帮助来自哪里；不能让孩子只剩下照做。

项目希望支持的过程是：

> 孩子提出想法 → 共同确认理解 → 孩子选择一个小目标 → 动手尝试 → 观察与讨论 → 孩子决定怎样改 → 讲述自己的发现。

采用 PBL（项目式学习）方式，让问题、试验、修改和表达围绕她真正想做的作品展开。先陪一个孩子完成真实项目，再根据实际经验支持其他小朋友，不先建设完整课程平台。

## 2. 织界空间的定位与项目分工

用户规划中的织界空间首先是孩子有条件动手探索的“实验室”，不只是作品展厅。实体空间和网页 3D 场景如何对应、如何连接，仍需后续设计，不视为已完成的数字孪生。

| 角色 / 载体         | 计划职责                                                         | 边界                                               |
| ------------------- | ---------------------------------------------------------------- | -------------------------------------------------- |
| 孩子                | 提出愿望、选择目标、搭建试验、观察结果、讲述作品                 | 不是替平台验证功能的执行者                         |
| G 老师              | 拆解小挑战、提问、解释、提供适量提示和技术支持、帮助复盘         | 不替孩子作出所有决定，不代替现场安全判断           |
| 家长 / 现场成人     | 准备材料、检查设备、保障安全、反馈现场信息，作为共同导师支持孩子 | 不为追求进度而包办孩子能够尝试的部分               |
| Loom OS             | 掌上创作和控制工具，让界面、动画与真实作品建立联系               | 真机与外设链路需单独验证                           |
| Loom Web / 织界空间 | 实验室的门户和数字部分，按需承载项目、资料、过程和作品           | 不把现有 3D 场景编辑能力等同于机器人仿真或实物控制 |
| 实体实验环境        | 支持安全搭建、观察、交流和反复试验                               | 布置与设备选型待确认                               |

## 3. 首期参与者背景

以下来自家长在 2026-11-03 的补充，仅作为活动设计背景，不作为公开宣传素材：

- 首期参与者为家长的女儿，7 岁，一年级。
- 家长表示“我之前搭过乐高的小车”；这说明家长有相关搭建经历，不能据此认定孩子已独立搭过小车。
- 孩子还没有完全独立动手的经历。
- 她明确想要自己的机器狗，这是首期项目的愿望起点；拟以乐高加控制模块，探索通过 Loom OS 操控四足机器狗。
- 后续希望邀请其他小朋友参与；人数、年龄、协作方式尚未确定。

### 针对此起点的教学建议（活动草案）

- 首次活动以口述、画图、挑选零件和小规模搭建为入口，不预设她会读代码、接线或理解电机参数。
- 不要求她立即独立完成整只机器狗，先让她完整主导一个可观察的小任务。
- 一次只提出一个清楚的小挑战，解释尽量短，使用实物和图示；活动时长由现场参与状态调整，不先承诺固定课时完成。
- 提示按“提问 → 线索 → 可比较的办法 → 示范”逐步增加；既不直接给全套答案，也不让孩子长时间猜成人想要的答案。
- 每次结束让她用自己的话讲一个发现；可由成人代记，不要求写长报告。
- 首次活动再观察她的兴趣、理解方式和希望得到的帮助，不根据年龄给她贴能力标签。

## 4. 首期项目：自己的四足机器狗

### 4.1 驱动问题

> 怎样做一只属于你的机器狗，让它听懂你用掌上设备发出的指令？

机器狗是她已经提出的愿望，不需要重新选题。开场围绕“你的机器狗是什么样的、你最希望它先做什么”展开，再一起拆出第一个可尝试的小目标。实现路径可以分阶段，不能因教学便利而把她想要的机器狗替换成成人预设的其他作品。

### 4.2 建议挑战顺序

这些是可调整的里程碑，不是已确认的课表；实际顺序需结合孩子选择、机构方案和设备验证结果。

| 挑战              | 留给孩子的选择或探索                             | 阶段成果                         |
| ----------------- | ------------------------------------------------ | -------------------------------- |
| 认识我的机器狗    | 名字、样子、为什么想做、最想实现的一件事         | 图画或口述，以及一个首要愿望     |
| 让身体站住        | 腿的位置、支撑与姿势，比较哪种搭法更稳           | 一个可站立的静态模型             |
| 让一个地方动起来  | 哪个关节先动、观察不同动作的结果                 | 成人检查后可重复的小动作         |
| 用 Loom OS 指挥它 | 按钮的图案或名字，以及按钮对应的动作             | 一个按钮触发一个已验证的确定动作 |
| 挑战走出一步      | 比较动作顺序、观察倾倒或移动，只改变一个条件再试 | 一次有观察记录的步行动作实验     |
| 介绍我的发明      | 自己作了什么选择、遇到什么问题、下次想改什么     | 面向家人或受邀小伙伴的演示       |

第一次按下自己命名的按钮，让亲手搭建的作品动一下，可以是独立的阶段成果；不能把单关节运动描述为“机器狗已会走路”。如孩子仍希望它走路，应保留这个目标，诚实记录尚未实现的部分。

### 4.3 两条准备线

- **面向孩子：** 简短任务卡，包含今天的小目标、先猜一猜、试一次、比较结果。
- **面向家长：** 幕后准备卡，包含材料、已验证能力、成人操作项、提示建议、停止条件和备用活动。

成人提前排除危险和无意义的环境故障，但不替孩子消除所有值得探索的问题。如果运动链路尚不可用，可以继续静态搭建、画控制界面或观察动作；必须说明这不是实物控制已完成。

## 5. G 老师的现场协作方式

### 5.1 观察、确认、引导，而不是接管

- 区分观察事实与推测；看不清、听不清或没有收到信息时明确说明。
- 孩子指着作品提问时，先确认她指向的部位和刚才的操作，不要求她先使用专业术语。
- 孩子专注探索时少插话，允许她主动说“让我自己试一下”。
- 普通探索不需要逐步等待 AI 批准；涉及通电、机构运动等风险时，由现场成人把关。
- 不持续评价孩子，不做能力排名；反馈围绕具体观察、方法和选择。

示例：孩子说“它又倒了”，G 老师先确认倾倒方向和被遮挡的支撑点，引导孩子观察、提出原因、选择一次修改，再比较结果，而不是立即指定一个未经验证的电机角度。

### 5.2 帮助来源保持透明

| 类别           | 示例                                   |
| -------------- | -------------------------------------- |
| 孩子决定       | 作品目标、外观、行为、先试哪种办法     |
| 共同探索       | 为什么失败、如何比较方案、下一次改什么 |
| 成人和工具提供 | 安全供电、基础驱动、复杂代码、设备维护 |

不以代码行数、是否完全无帮助或成品是否漂亮衡量“独立”。更关注她能否说明自己作出的选择，描述一次观察，并参与下一次修改。

## 6. 观察与交流硬件规划

用户确认可以配备摄像头、麦克风、屏幕等硬件，让 G 老师更好地理解孩子的操作与疑问。此处记录需求，不锁定型号、采购清单、传输协议或服务供应商。

| 输入 / 设备                | 要解决的问题                     | 初期建议                                 |
| -------------------------- | -------------------------------- | ---------------------------------------- |
| 工作台摄像头               | 观察搭建、零件和指向             | 优先拍手和作品，不以拍脸为目标           |
| 可调整的近景视角           | 看清关节、连接处和被遮挡部位     | 先判断主视角是否足够，再决定是否增加设备 |
| 麦克风与扬声器             | 自然提问、听到简短回应           | 明确开始、静音与结束状态                 |
| 屏幕                       | 展示一张图、一个动作或当前小挑战 | 服务动手，不把活动变成持续观看           |
| Loom OS / 控制模块状态反馈 | 区分按键、命令发送和实际执行     | 不能把 UI 动画当作硬件成功证据           |

建议先验证一个工作台视角、语音交流和一个显示屏组成的最小环境。摄像头和麦克风的存在不代表 AI 已能持续看见或听见；需验证实际接入、清晰度、延迟、遮挡、噪声和信息缺失时的处理。

## 7. 安全与隐私边界

以下作为后续设计约束，不代表现有系统已实现这些机制：

- 接线、供电、工具使用和机械检查由现场成人负责；AI 不作现场安全保证。
- 模型不得自由生成任意指令直接驱动机构。动作须经过验证、限制范围，并由现场确认触发。
- 停止方式与断连处理应在成人预检中实际验证；失联后的具体安全状态需结合机构设计，不能一概假定断电就是安全。
- 没有清晰观察和可靠停止条件时，不进入相关运动试验。
- 不默认全程录音录像；采集、上传、保存、访问范围和删除方式需先明确，并由家长确认。
- 摄像头、麦克风应有清楚的采集状态和关闭方式，尊重孩子暂停交流或不被记录的意愿。
- 记录尽量只保留作品和必要实验信息，不收集与项目无关的身份、学校、位置等信息。
- 展示先限家庭或受邀小组；公开发布需家长确认并尊重孩子意愿。当前公开只读分享功能不等同于私密小组访问控制。
- 本文中的年龄和学习背景不自动进入官网文案、公开作品页或发布素材；文档公开前应复核必要性与隐私范围。

## 8. 已有基础与尚未验证的能力

以下仅据 2026-11-03 阅读的两仓库 README 记录，非本次真机测试或完整代码审计结论：

- **Loom OS：** 文档标注 0.1.1 集成候选，已有应用运行时和设备 API 基础；主机侧测试状态不能替代仍待完成的 Mosaico 真机验收。Network / Agent / Creator 的设备适配器或 Provider 仍需接入或验证。
- **Loom Web：** 已有门户、3D 场景及个人空间编辑、保存和分享能力；当前 Agent 为受限场景操作，不是现场教学系统或机器人控制系统。
- **跨项目链路：** 音视频观察、G 老师现场交互、Loom OS 到机器狗的真实控制，以及完整活动流程，均未在本计划中验证。

参考：本仓库 [README](../../README.md)、[个人空间 MVP 规格](../specs/loom-space-mvp.md)；Loom OS 仓库的 `README.md`、`Loom-OS-Development-Plan.md` 与 `Mosaico-Patch01-08-Device-Checklist.md`。

本计划不解除现有技术门禁：Loom OS 的真机验收要求仍有效；个人空间 MVP 明确不做的实物控制也不会因本计划而自动启用。后续开发必须先摸清已有功能和接口，优先复用；确需新增能力时单独提出设计并取得授权。代码审查由主 agent 执行，不交给子代理。

## 9. 推进顺序与待确认事项

1. **计划留存（本次范围）：** 记录已确认方向、孩子背景、活动草案与能力边界。
2. **细化她的机器狗想法：** 从已明确的机器狗愿望出发，听她描述样子、最希望先实现的行为和愿意自己尝试的部分，不重新确认项目选题。
3. **成人技术预检：** 盘点已有乐高、控制模块与 Loom OS 真机；验证最小控制链路、停止机制，以及观察和语音方式。
4. **准备首次活动：** 基于预检结果编写一张孩子任务卡和一张家长准备卡，再确认安排。
5. **完成一次真实探索并复盘：** 记录她原本怎么想、实际发生什么、后来改了什么，以及哪些帮助有效。
6. **按需扩展：** 再判断需要哪些网页记录、实验室功能或多人协作支持，不预先建设庞大平台。

仍待细化或确认：她想要的机器狗的具体样子与首要行为（机器狗这一愿望已明确）；现有积木、执行器、控制板与供电条件；Loom OS 真机状态和可用通信能力；实验台布置；音视频接入与数据处理方式；首次活动的时间与节奏。

暂不承诺：完整四足步态的完成日期、具体硬件型号、自动生成并执行任意动作、持续实时视觉、完整数字孪生、课程账号系统、能力评分、多人实时协作或公开发布。
