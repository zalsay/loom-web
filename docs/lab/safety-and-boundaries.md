# 织界实验室｜技术安全适配、隐私与项目边界

返回[执行框架总览](README.md)。本文档定义具体项目的现场技术与安全核对要求、活动记录与儿童隐私原则，以及与现有仓库能力的技术边界。

## 1. 当次项目的技术与安全适配

只在确定当次想法后补充相关约束，不把某个示例的零件、数值或结构推广成通用要求。

- **材料与制作项目：** 核对实际材料、连接方式、工具和成人操作范围；具体结构另行设计，不能凭缺失的照片或尺寸保证可行。
- **电子或运动项目：** 核对器件规格、供电、受控动作、停止与失联处理；没有预检就不进入相关操作。参数与响应指标由当次项目确定，不套用示例固定值。
- **数字创作项目：** 先验证实际可用能力和保存方式，避免把界面演示当成功执行。
- **有即时交互的项目：** 预先配置并验证确定性操作，现场按键不依赖每次大模型推理；本地控制和响应目标按项目需求验证，不承诺未经测量的性能。
- **能力不足时：** 与孩子商量缩小目标、换材料、做演示或延期；说明当前替代与原目标的区别，不悄悄更换她的愿望。

任何设备、材料或服务建议都不自动构成采购、部署、付费或外部上传授权。现场安全由成人负责，AI 不能仅凭画面保证安全。

## 2. 记录、隐私与已有项目边界

每次只需记录：她想做什么、选择了哪一小步、试了什么、发现什么、成人提供了哪些帮助、下次是否继续。不做能力排名，不强制拍摄或公开展示。

摄像头、麦克风与素材保存/分享方式需明确并经确认，尊重孩子拒绝记录的意愿。家长此前同意公开计划中的年龄与学习背景，不自动授权公开新照片、声音、作品素材或其他儿童信息。

Loom OS 与 Loom Web 是可选支持工具，不是活动必须使用的完整教学平台。各仓库的现有能力、真机验收和部署边界仍有效；不能假定已支持持续音视频理解、任意素材展板、设备直连或私密儿童档案。

参考本仓库 [README](../../README.md)、[个人空间 MVP 规格](../specs/loom-space-mvp.md)；Loom OS 能力与真机要求以其仓库文档及实测为准。后续开发先摸清已有功能，确需新增能力时单独提出设计并获得授权；代码审查由主 agent 执行。
