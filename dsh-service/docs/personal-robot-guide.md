# 一人一台墨水屏：G 老师个人指导原型

**产品决定**：G 老师在孩子搭建时提供指导，不是做完后才填写的记录器。每人一台，项目私有。Team 是可选的线下互助入口，不是一个全员聊天会话。积分只记团队贡献，不决定谁能用工具、继续参加或优先提问。

## 决策更新：Pad 是 Agent 宿主（2026-11-25）

以下为目标架构；下文 Node 服务接口和单测仅作早期行为原型，不是目标部署拓扑。Metalio E-Ink 4 Plus 的原生固件内集成 ESP-Claw：`claw_core` 在 S31 组织回合、选择上下文和调工具，设备存储保存按绑定代次和项目隔离的 memory。远端提供 ASR/LLM 等推理端点；设备认证与授权另计，不在云端再跑第二套教学循环。换网络不换档案；换机不自动找回旧档案，需要显式迁移。

### Agent 自用的 Lua 工具：创造、更新与调用（设计，未实现）

Loom 新增的是 **Agent 自用的工具插件**；不是把 ESP-Claw 的 UI 创造改成工具，也不是用固定 PadUI 取代它。两条路径并存：

- **工具路径**：Agent 生成、验证、注册 Lua 工具，之后按工具名与参数调用。结果返回 Agent 回合；无需页面、按钮或孩子手动安装工具。涉及拍摄等敏感操作时，UI 可代收单次授权，不负责执行工具。
- **界面路径**：保留 ESP-Claw [Lua/LVGL](https://github.com/espressif/esp-claw/tree/50072775cfa20d7ce25a9b27591d9d7c8b9dbab5/components/lua_modules/lua_module_lvgl) 创造交互页面的能力。需要展示时，Agent 可以另外生成页面，由 UI 宿主加载；页面不因此获得通用工具调用权限，工具也不因注册而自动产生 UI。

两条能力独立验收：不挂载 UI，Agent 仍能创造并调用工具；不创建任何新工具，仍能在 Metalio 上生成、显示、交互并退出一个 Lua 页面。后者需真机验证原厂显示与触控适配。

1. 创建：Agent 在处理任务时发现缺少可复用的能力，可主动请求模型生成候选 Lua 和声明（工具名、版本、输入 schema、所需能力、运行预算、原生 API 最低版本），写入本机草稿区，不直接执行。设备凭证不进草稿或模型上下文。
2. 测试：先用模拟输入和无副作用能力试跑；工具不能借测试自动获得摄像头或共享数据权限。端侧验证名称、参数、允许的能力，以及内存、输出、耗时上限。上游 `cap_lua` 可执行脚本，但其默认标准库和超时钩子不是不可信代码沙箱；完成受限执行器前，只运行审核过的包。
3. 激活：在本机保存不可变版本，校验成功后原子切换活动版本；设备在下一次构建模型工具目录时发布新描述，并在调用时再次校验。旧回合固定旧目录和版本，失败或写入中断保留上一可用版本。纯 Lua 逻辑更新不刷固件；新增驱动或原生权限仍需固件发布。
4. 调用：模型看到业务工具名，而非任意脚本路径。原生分发器只运行已激活版本，并按绑定代次、项目及单次用户授权执行。摄像头只通过预设网关接口请求当前工位；网关处理 RTSP 并回传媒体。脚本不能拿到摄像头地址、凭证、任意网络或直接操控电机。
5. 真机验收：给 Agent 两次已确认的实验记录，问“换短尾巴后有什么变化？”Agent 创建或复用无联网的 `compare_observations`，用模拟输入试跑、激活，再按名称调用，拿到差异数据后组织自然语言答复。测试无需挂载 PadUI；热加载不增加界面入口，不重启也不刷机。升级时旧调用仍返回旧版结果，错误更新不会替换可用版本；重启能恢复已激活版本；解绑后原孩子的私有工具和记忆对新绑定不可见。

上游参考：[Agent 循环](https://github.com/espressif/esp-claw/blob/50072775cfa20d7ce25a9b27591d9d7c8b9dbab5/components/claw_modules/claw_core/src/claw_core_agent_loop.c)、[Lua 能力注册](https://github.com/espressif/esp-claw/blob/50072775cfa20d7ce25a9b27591d9d7c8b9dbab5/components/claw_capabilities/cap_lua/src/cap_lua.c)、[Lua 执行器](https://github.com/espressif/esp-claw/blob/50072775cfa20d7ce25a9b27591d9d7c8b9dbab5/components/claw_capabilities/cap_lua/src/cap_lua_runtime.c)。

## 从原型继承什么

原来的共享农场 PWA 使用设备会话＋身份声明＋声纹挑战；保留它，不把它当作新设备的默认入口。个人终端复用公平队列、单案租约、转写后确认、服务端筛查。为机器人创建独立队列，记录绑定孩子与 `projectId`，不是借用一个虚拟地块。设备配对只证明哪台设备有权访问，不证明实际说话者是谁：借用、遗失、退组时须能锁定和撤销绑定。

## 给孩子的三个入口（APPUI 接口设计，尚非实际 UI）

| 入口         | 触发与输出                                                                     | 服务核心                                                                                                                             |
| ------------ | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 接着做       | 默认显示本项目最近一张有效提示；正在等答复时显示等候，不清空上一条。默认安静。 | `privateView(session)` 读本人当前项目记录，由界面选取显示。                                                                          |
| G 老师，帮我 | 按住说话、松开转写；孩子可听／看原文，确认或重录。确认之后才进入指导队列。     | `record` → `confirm`；Host 调用 `runOne`，一轮隔离上下文只处理一个孩子的案卷。Agent 从允许的机器人单步卡中选择，不直接生成电机指令。 |
| 找队友       | 自己选模板发卡，队友领取，面对面观察，双方确认后小队 +1。                      | `publish` → `claim` → `confirm`；`board` 仅读本队。个人转写、原始录音和案卷不会随卡发送。                                            |

例：尾巴装好了却不摆动，可以提交“请帮我观察”的卡。另一个孩子在自己的设备接受；两人回到桌边，观察并确认合作。即使没有修好，也能完成这次互助。不比较谁的机器人先走起来，不为用屏幕的时长或对话条数加分。

## 用设备 UUID 绑定孩子

- **固件读取既有标识**：复用上游 [`Board::GetInstance().GetUuid()`](https://github.com/CloudZao/Metalio-E-INK4-Plus/blob/main/main/boards/common/board/board.h)。上游将随机 UUID v4 保存于 [`board` 的 `uuid` 设置](https://github.com/CloudZao/Metalio-E-INK4-Plus/blob/main/main/boards/common/board/board.cc)。它不是不可变硬件序号：保留设置的重启与更新应保持 UUID，擦除该设置后会生成新 UUID。需在目标批次上验证刷机是否保留设置。
- **初次配对**：设备读取 UUID，向 Loom 申请短时、一次性的配对码并在屏上显示；已登录且有权管理该孩子的家长或管理员在管理端选择孩子并确认。服务端保存 `deviceUuid → childId`，在设备通过配对流程领取凭证后，本机安全保存专用、可撤销凭证。UUID、MAC 或孩子 ID 都不能代替设备凭证。
- **日常使用与换机**：终端通过 HTTPS 持凭证访问，由服务端解析当前孩子及其有权访问的项目；不接受客户端自报的孩子 ID 作为授权依据。换机或设备易主时撤销旧凭证、重新配对，清除旧绑定的本地私有缓存。项目记忆只保存在绑定设备上，换机需显式迁移。撤销在线凭证不能擦除离线设备；本地记忆和工具需有访问保护，设备易主前须在本机清除。
- **验收**：两台设备分别绑定不同孩子，切换家庭 Wi-Fi 后仍正确识别；只有 UUID、没有有效凭证不能读取案卷或调用 ASR；换机后旧凭证失效；清除设备设置后要求重新配对，不自动恢复旧绑定。

## 家庭与营地共用的服务端 ASR

个人终端无论在营地还是回家，都连接同一个可通过公网 HTTPS 访问的 Loom 入口，不再依赖营地旧笔记本或同一局域网。E-Ink 4 Plus 自定义固件仅在孩子主动按住说话时采音，松开后上传短录音；Loom 校验设备绑定后调用 ASR，返回转写；孩子确认后，才将文本交给个人项目的 G 老师。Pad 在本地持久化孩子确认的项目进度；更换网络只改变模型端点的连接，不改变记忆来源。音频不随求助卡共享。

ASR 实现独立于终端协议：可以在托管服务器自跑 SenseVoice，也可以由 Loom 调托管 ASR API，首版供应商待定。若用第三方，密钥仅在服务端，接入前核实儿童录音的处理与保留条款并告知监护人；Loom 默认不长期保存原始录音。断网时可在当前会话展示已缓存的提示，明确不能转写；没有受保护的持久缓存时，断网重启只显示连接提示，不恢复私有卡片。恢复联网后不自动补传旧录音。公网只开放受设备认证与限流保护的终端 API，不开放管理口。

家庭场景验收：同一台设备离开营地、换到家庭网络后，仍能完成录音、转写确认与指导，并取回同一个私有项目的进度。用手机热点做一次跨网络测试，再检查断网提示和设备撤销后的拒绝访问。

## 运行边界和下一次验收

- **已做**：内存业务核心；设备身份由受信 Host 注入；单步卡、私有上下文、小队模板与双确认计分。测试用替身提供转写和选卡，不需要安装模型。复现：在仓库根目录执行 `node --test dsh-service/test/*.test.mjs`。
- **尚未做**：Loom 自有 Agent Harness 的真实推理适配、设备配对与撤销、持久化、网络队列、真实 ASR/TTS、墨水屏 APPUI 与固件。名字里的 `dsh-service` 是原有试验目录，不表示孩子端要用 DSH、也不表示需要更改当前 DSH 插件配置。真实适配必须为每案提供干净上下文，不能沿用混有他人历史的模型线程。
- **现场成人**：不逐条审批正常提问，负责电源、工具、现场安全。固定提示不认证设备安全、不自动下发控制指令。语音按键触发，Host 应做授权、音频格式/时长/大小限制，不默认留存录音。
- **上机前**：补设备令牌和服务端配对、掉线重试与持久化；私有案卷按孩子＋项目索引，跨周可恢复；计分须把完成事件与积分增量作为一次原子提交，断线重传不多加。限制恢复/转移后旧设备的读取；无网显示已确认的缓存卡，不显示伪造的新建议。
- **首轮验收**：两台个人终端同桌提出不同的问题，各自收到与作品相关的一步；陌生设备看不到案卷；未经分享队友看不到原话；不同项目的同队孩子互助只加一次分；涉及危险操作显示停手找成人；第二周开机还能接着上次做。最后一项要等真实持久化和真机验证，单测不代替现场验收。
