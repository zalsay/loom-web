# FlashDuck 第一期：手机热点手柄与 Pad 蓝牙手柄

**首选方案（设计，尚未实现）**：鸭子开带密码的 Wi-Fi 热点并提供本地网页，手机连热点后用 Safari 或 Chrome 操作五档颈位。不需要小程序、BLE、Agent、公网或场地电脑。网页、图标和脚本随固件提供，不从 CDN 加载。需要改用 Loom Pad 时，从网页配置「连接 Pad」，按下面的流程交接到原生 BLE 手柄；现有场地网关保留作调试，不是热点模式的部署前提。

**使用路径**：连接指定鸭子的 Wi-Fi → 即使提示无互联网也保留连接 → 浏览器打开印在说明卡上的本地地址（规划 `http://192.168.4.1/`，需固件固定此地址）→ 成人在鸭端确认控制 → 孩子按键。Wi-Fi 入网码与网页地址是两个步骤，不依赖系统自动弹出门户。仅在热点接口提供手柄；连上 Wi-Fi、打开页或刷新页都不能直接发动作。鸭端签发短时、单控制者会话；浏览器仅提交方向与请求 ID，不提供底层密钥或任意角度入口。首版不把热点桥接到公网。

## 手柄首页与操作约定

```text
赛博鸭手柄       鸭子：01      状态：可操作
                 控制：头部
[ 向左看 ]      [ 回正 ]      [ 向右看 ]
[ 稍向左 ]                    [ 稍向右 ]
最近指令：—                  [ 退出控制 ]
```

用大触控键、黑白文字状态，只有状态改变才局部刷新。五个键分别对应 `left / center / right / slight_left / slight_right` 的绝对颈位，不是身体转弯。每次点按只提交一次，不长按连发、不排队。手柄为一次点击保留稳定的请求 ID，经同源 HTTP 提交，鸭端校验控制权、校准范围、忙状态和重复请求，不经模型工具注册表。

| 情况 | 手柄表现 |
| --- | --- |
| 未绑定、离线或未解锁 | 显示鸭子与原因，方向键不可用；连接本身不触发动作。 |
| 已受理 | 显示「执行中」，暂时禁用动作键，只查询原请求。 |
| 控制输出结束 | 显示「指令已结束」并恢复可操作；不写「鸭头已到位」，因为没有角度反馈。 |
| 断线、失败或结果不明 | 显示原因；不自动重发，结果不明时锁键并提示现场核对。退出或重新连线也不补发。 |

「退出控制」只停止接受新输入，不能终止已开始的轨迹；「回正」也是动作，不是急停。成人须能独立切断舵机动力。首期不显示尚无确定性执行接口的前进、后退或身体转向按钮；自动巡视、视觉回充、Agent 自主动作不在首期范围。

**首期验收**：场地电脑和路由器均关闭，鸭子不配置模型密钥。iPhone Safari 和安卓 Chrome 分别连鸭热点打开页面；未解锁或已有另一手机控制时不能发动作。已获控制权的手机点一次「稍向左」，鸭端只接收一个动作；长按、刷新、掉线重连不补发，结果未知时保持锁键。上台架另验方向和行程。

### 从手机切到「连接 Pad」（双模设计，待实现）

1. 默认开机进入鸭端热点网页模式，BLE 不主动广播。成人在已授权网页选择「设置 → 连接 Pad」。只有执行器空闲、上一条结果明确时才接受切换。鸭子开启限时 BLE 广播（GATT 外设），网页保留连接，显示「等待 Pad，可取消」，暂时锁住网页动作键。
2. Pad 在「菜单 → 玩小鸭」中选择这只鸭（GATT 中心设备）。首次绑定需现场确认；陌生设备不能凭名称接管。仅建立蓝牙连接不算交接成功：已授权 Pad 完成控制服务握手、能接收状态回执后，鸭端才一次性撤销旧网页控制权、授予 BLE 控制权。网页显示「Pad 控制中」，不再接受动作。首版可保留热点作只读状态入口；Wi-Fi 与 BLE 共存的内存和功耗须实测。
3. 取消、超时或配对失败：关闭本次广播，不执行动作；仍有效的原网页会话可继续控制。BLE 控制中掉线：锁键，不自动交回手机、不补发旧指令。可由已绑定 Pad 重新握手，或由成人在鸭端实体确认返回热点模式，再领取新网页会话。已保存绑定不等于上电解锁。
4. 验收：网页上点击一次切换，Pad 可接管原五档颈位；等待时不能发送动作；交接后旧网页请求被拒绝；另一台未授权 Pad 不能抢占。配对失败、两个手柄同时按键、BLE 掉线及重新上电均不应引起额外运动。Pad 可保持连接自己的 Wi-Fi，蓝牙只传控制与回执。

以下两段 HTTP 接口是已实现的网关版，不代表鸭端热点网页或 BLE 服务已可用。

## 与原有聊天版的区别

原来的 [DuckClaw 聊天适配](../flashduck/README.md) 不变。新接口的鸭端是**独立编译的直控专用镜像**，不是在原厂聊天固件运行时追加一个公开 URL。两种能力保留在不同固件里；同一台鸭同一时刻不会既开 `/ws` 与自动情绪动作，又让 Pad 写同一个舵机。不能用新网关去控制没有安装直控镜像的鸭。只在固定版本的[上游工程](https://github.com/FlashCat-Jordan/Flashduck/tree/9d4316e3f1f7ef693be4d62f4b1aa020a3daedf4/firmware/duckclaw)旁生成新项目，不覆盖原始源码。DuckClaw 使用 CC BY-NC-SA 4.0，商业场地使用前请确认授权。

## 两段接口

| 调用方 | 协议 | 约束 |
| --- | --- | --- |
| Pad → 场地网关 | `POST /v1/duck/look`，JSON `{duckId,requestId,direction}`；`GET /v1/duck/look/:requestId` 只读 | `direction` 支持 `left`、`slight_left`、`center`、`slight_right`、`right`。微调是当前侧端点与校准中位之间的半程位置，不是每次累加；该侧距离不足 2° 时拒绝微调。首期由手柄按钮选择方向，Pad 宿主提供绑定和稳定请求 ID。网关只监听 loopback；真实 Pad 需受保护的现场代理和设备认证，不能直连裸 HTTP 公网。 |
| 网关 → 鸭 | 先 `GET /control/v1/status`，后 `POST /control/v1`；`GET /control/v1/status?id=...` 查询 | 独立设备凭证、指定私网 IP、选定的本机校准范围、颈部专用、固定过渡时间 700ms。命令绑定本次开机 `sessionId` 以及设备 uptime 的短期截止时间。每次启动须现场确认居中、解锁才允许动作。 |

`accepted` 表示命令已受理，`command_finished` 表示固件按轨迹发完控制输出；没有位置传感器，**`motionVerified` 始终为 `false`**。同一个意图重试查询，不自动重发动作。网络中断、跨重启或结果无法核实时为 `unknown`，保持锁定并由现场人员核查。停止进程、断开网络、回中指令都不是断动力。

## 后续实验：一次左右巡视（非首期手柄功能）

`duck_look` 是单次定位；`duck_scan({})` 是可选的 Pad 工具，以「小幅左 → 小幅右 → 回中」执行一遍，没有自由序列、无限循环、步行或摄像能力。两侧各停留约 300 ms 后才启动下一段。子步骤用独立、稳定的请求 ID，只有读到 `command_finished` 才前进。不确定、网络错误或授权取消时不再发下一段（包括回中），已经开始的一段可能仍会完成。不能把左右巡视当作视觉识别或已找到充电座。

接入真 Pad 的工具宿主必须在单只鸭范围内独占这次扫描（含普通转头和其他控制者），为每个意图提供不可重放的授权、单调时钟和可取消的 worker 等待。当前 USB/HTTP 固件协议不变，未额外提供跨 Pad 的扫描租约；没有配套宿主就只启用单步工具。

## 工作站模拟（不依赖实物）

推荐 Node 22+。从仓库根目录运行；只需启动模拟 CLI 即可自行调用 HTTP，自动验证另起临时端口，不需要 CLI 同时运行：

```sh
DUCK_PAD_TOKEN="$(openssl rand -hex 32)" node dsh-service/flashduck-direct/serve.mjs
node --test dsh-service/test/*.test.mjs dsh-service/flashduck-direct/test/*.test.mjs
# 若尚无官方 WASM 资产，先运行 sh dsh-service/flashduck-sim/download.sh
node dsh-service/flashduck-direct/pad/verify.mjs --loopback
```
