# Metalio E‑Ink 4 普通版：分享项目卡、从手机加照片

仅用于 [CloudZao/Metalio-E-INK4 固定提交](https://github.com/CloudZao/Metalio-E-INK4/tree/d12f481f4a42420634bb56a928f3959a977367d4)，**不是 Plus**。这是源码补丁，不是可刷写的二进制。在原厂「设置 → 存储」下分别加入「分享当前项目卡」（给别人看）和「从手机加照片」（给当前项目收照片）。两项服务不能同时开启，均不需要公网、手机 App 或电脑中转。

## 应用与构建

从本工程根目录运行。请另建干净固件工作副本，不要在正在开发的固件目录里试装。

```bash
git clone https://github.com/CloudZao/Metalio-E-INK4.git /tmp/metalio-card-fw
git -C /tmp/metalio-card-fw checkout --detach d12f481f4a42420634bb56a928f3959a977367d4
python3 dsh-service/pad-share/metalio/apply.py --check /tmp/metalio-card-fw
python3 dsh-service/pad-share/metalio/apply.py /tmp/metalio-card-fw
(cd /tmp/metalio-card-fw && . ~/esp/v5.5.4/export.sh && idf.py build)
```

构建需要上游指定的 **ESP-IDF 5.5.4** 工具链（按实际位置调整 `export.sh`）。使用原厂跟踪的 `sdkconfig`，不要 `set-target` 或用 Plus 配置替换它。补丁开启 `CONFIG_LV_USE_QRCODE`；Canvas 在该提交已启用。安装器将相邻 `component` 下列明的构建输入（含接收端、手机页面）复制到原厂 `components/pad_share`。`--check` 不写入；安装拒绝非固定提交、补丁冲突及已存在的同名组件。原厂 `.gitignore` 默认忽略新的 `components/*`，维护自己的分支时请勿漏掉组件。

## 准备 SD 卡：一个当前项目，一个收件目录

以下路径相对 **SD 卡根目录**（固件中是 `/sdcard`）：

```text
metalio/e-ink/project/
  current.id              ← 接收照片必需。例：robot-arm-01
  current.html            ← 只读分享必需。仅接收照片不需要它
  robot-arm-01/photos/    ← 服务创建；本项目收到的 JPEG
```

上游没有完整的 G 老师多项目 App。**此补丁不会根据当前 HTML 的标题或文件名猜项目。** 单一可信的项目标识来自 SD 卡的 `current.id`，示例见 [current.id](./current.id)。文件一行，仅用 1–32 个小写 ASCII 字母、数字、下划线或连字符，不用 FAT 保留设备名，不要加空格、引号或 BOM。每个不同项目分配不同标识；重复标识意味着同一收件目录。缺少或非法时不允许接收，原只读分享仍不依赖它。

若由项目 App 接管：切换前必须先停止接收并等其返回，再更新项目卡和标识，最后才允许新项目发起接收。不要在开放会话中原地截断、改写文件。手工切换时先关闭接收，再通过 SD 读卡器或模拟 U 盘替换 `current.id`（及需要同步的 `current.html`），安全弹出并关闭模拟 U 盘。已保存照片不会随切换迁移或删除。

## 手机 → 当前项目：收照片和找回照片

1. Pad 和手机接入**允许终端互访的同一 Wi-Fi**；Pad 需纯 STA 模式、已关联并获得 IPv4。不支持蜂窝、热点或 AP+STA。
2. 打开「设置 → 存储 → 从手机加照片」。先核对屏幕上的**项目标识和 SD 卡位置**。此时尚未启动网络服务，仅查照片位置不需联网。如标识不对，请关闭，不要开始接收。
3. 点「开始接收照片」，用手机浏览器扫码或手输**完整 URL**，选照片并上传。一次会话最多接收 8 张，每张传到 Pad 的 JPEG 最多 1 MiB。Pad 显示本次成功接收数；它不是整个项目的历史总数。二维码不可用时仍可手输，必要时在屏幕中滚动查看。
4. 点「停止接收并关闭」或离开页面；5 分钟到期、断网、项目标识变化或 SD 卡不可用也会终止接收。旧链接不应继续接收。停止不会删除此前成功的照片；中断时以**手机的成功回执和目录里的最终 JPEG**为准。
5. 再次打开「从手机加照片」即可查看该项目目录，不必另开会话。要取出照片，先停止接收，再用模拟 U 盘或读卡器打开对应 `metalio/e-ink/project/<id>/photos/`。这里没有相册解码、历史缩略图或自动改写 HTML 的功能；完整 App 应按同一标识引用该目录。请勿在接收中启用 U 盘、热拔卡或修改项目文件。

## 当前项目 → 同学：原有只读分享

把希望公开的单份 UTF-8 HTML 放到 `metalio/e-ink/project/current.html`（最多 64 KiB）。「设置 → 存储 → 分享当前项目卡」发送本次静态快照；不查项目照片目录，也不给别人写入权。卡缺失时不扫描全卡找替代。内联脚本、外链和交互式 HTML 不按原样保留；修改源文件不改变已分享快照。点「停止分享并关闭」立即撤销，离页或默认 5 分钟到期也会关闭。已下载的内容无法撤回。

两个入口都使用局域网 HTTP，持完整有效链接即可行使对应权限。不要公开截图或记录仍有效的地址。若同 SSID 仍不可达，先检查访客网/客户端隔离，不要为此打开无密码热点。

## 验证边界与上板清单

已用普通版固定提交的干净工作树验证 `--check` 不写入、实际安装、`git diff --check`、8 个组件输入逐字节比对及拒绝重复安装。将安装后的界面源与主机端 LVGL/SD/服务替身编译后，实际调用页面回调验证了：开启前不监听、缺标识/开局前标识变更拒绝、计数刷新、运行中 ID 变化或 SD 失效撤销、二维码失败仍显示 URL、到期及关闭清理。这不是原厂全量 ESP-IDF 编译，也没有刷机、实测墨水屏扫码或 SD 热拔。最低上板验收：

- 无标识、非法标识、模拟 U 盘占用、无 Wi-Fi：不得显示可用上传 URL；只读项目卡应继续独立工作。
- 两个不同标识分别接收一张；核对手机成功回执、Pad 本次计数、各自目录内容。离开后重新打开只查目录不应开服务。
- 验证二维码、手输 URL、停止、待机/退出、超时、断网、卡丢失和旧地址重试；在部分上传时停止或切项目，不得在新项目落图。
- 验证 SD 满、空间不足和超限图片；观察内存水位、退出耗时及墨水屏刷新。界面不解码图片、不扫描整个目录；仅在计数变化时更新计数标签。LVGL 上的停止操作要等 HTTP 接收和当前 SD 操作退出，慢卡上可能短暂停顿。
