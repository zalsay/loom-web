# Metalio E‑Ink 4 普通版：扫码浏览项目卡列表、分享单张卡、从手机加照片

仅用于 [CloudZao/Metalio-E-INK4 固定提交](https://github.com/CloudZao/Metalio-E-INK4/tree/d12f481f4a42420634bb56a928f3959a977367d4)，**不是 Plus**。这是源码补丁，不是可刷写的二进制。在原厂「设置 → 存储」下有三个独立入口：「分享本项目卡片列表」供同学选卡浏览；原有「分享当前项目卡」只公开一张；「从手机加照片」只接收照片。一次只能开启一种服务，均不需要公网、手机 App 或电脑中转。

## 应用与构建

从本工程根目录运行。请另建干净固件工作副本，不要在正在开发的固件目录里试装。

```bash
git clone https://github.com/CloudZao/Metalio-E-INK4.git /tmp/metalio-card-fw
git -C /tmp/metalio-card-fw checkout --detach d12f481f4a42420634bb56a928f3959a977367d4
python3 dsh-service/pad-share/metalio/apply.py --check /tmp/metalio-card-fw
python3 dsh-service/pad-share/metalio/apply.py /tmp/metalio-card-fw
(cd /tmp/metalio-card-fw && . ~/esp/v5.5.4/export.sh && idf.py build)
```

构建需要上游指定的 **ESP-IDF 5.5.4** 工具链（按实际位置调整 `export.sh`）。使用原厂跟踪的 `sdkconfig`，不要 `set-target` 或用 Plus 配置替换它。补丁开启 `CONFIG_LV_USE_QRCODE`；Canvas 在该提交已启用。安装器将相邻 `component` 下列明的构建输入（含列表、接收端及手机页面）复制到原厂 `components/pad_share`。`--check` 不写入；安装拒绝非固定提交、补丁冲突及已存在的同名组件。原厂 `.gitignore` 默认忽略新的 `components/*`，维护自己的分支时请勿漏掉组件。

## 准备 SD 卡：一个当前项目，各自归档和收照片

以下路径相对 **SD 卡根目录**（固件中是 `/sdcard`）：

```text
metalio/e-ink/project/
  current.id              ← 分享列表或接收照片必需。例：robot-arm-01
  current.html            ← 仅原有单卡分享读取；列表和接收照片不用它
  robot-arm-01/cards/     ← 本项目愿意公开的归档 HTML（可为空）
  robot-arm-01/photos/    ← 服务创建；本项目收到的 JPEG
```

上游没有完整的 G 老师多项目 App。**此补丁不会根据当前 HTML 的标题或文件名猜项目。** 单一可信的项目标识来自 SD 卡的 `current.id`，示例见 [current.id](./current.id)。文件一行，仅用 1–32 个小写 ASCII 字母、数字、下划线或连字符，不用 FAT 保留设备名，不要加空格、引号或 BOM。每个不同项目分配不同标识；重复标识意味着同一归档和收件目录。缺少或非法时不能分享列表或接收照片，原单卡分享仍不依赖它。

若由项目 App 接管：切换前必须先调用 `pad_share_stop()` 并等其返回，再更新当前卡和项目标识，最后才允许新项目发起分享或接收。不要在开放会话中原地截断、改写文件。手工切换时先关闭分享或接收，再通过 SD 读卡器或模拟 U 盘替换 `current.id`（及需要同步的 `current.html`），安全弹出并关闭模拟 U 盘。已保存照片不会随切换迁移或删除。

## 当前项目 → 同学：扫码选卡浏览

1. 把愿意公开的卡放入 `metalio/e-ink/project/<id>/cards/` 的第一层，每张是非空且不超过 64 KiB 的 UTF-8 HTML，最多 128 张。`.html` 后缀不区分大小写；文件名可用中文，以 UTF-8 计最多 255 字节，不用控制字符、斜杠、反斜杠或冒号。不要把私人草稿放进来。相邻 `photos/` 不在列表内。列表**不自动公开**全局 `current.html`，以免误发上一个项目遗留的卡。确需将它列入本项目时，先核对内容，再以独立文件名复制进本项目的 `cards/`。
2. Pad 和手机连接允许互访的同一 Wi-Fi。Pad 点「设置 → 存储 → 分享本项目卡片列表」，核对标识，再点「生成只读二维码」。核对时不会启动服务；缺少标识不能改为浏览其他项目。
3. 手机扫码或在浏览器输入屏幕上的**完整 URL**，每页最多 12 项，点一张看详情。这个二维码不能用于上传。没有归档卡（包括还没有 `cards/` 目录）时，列表为空。归档名单在启动时确定，但详情在打开时才从 SD 读取。要增删、替换或重命名卡，请先停止再重新分享。
4. 点击「停止分享并关闭」撤销本次列表及详情链接。离页、默认 5 分钟到期、断网、SD 不可用或项目标识变化也会关闭。撤销不能收回已下载的内容。

## 手机 → 当前项目：收照片和找回照片

1. Pad 和手机接入**允许终端互访的同一 Wi-Fi**；Pad 需纯 STA 模式、已关联并获得 IPv4。不支持蜂窝、热点或 AP+STA。
2. 打开「设置 → 存储 → 从手机加照片」。先核对屏幕上的**项目标识和 SD 卡位置**。此时尚未启动网络服务，仅查照片位置不需联网。如标识不对，请关闭，不要开始接收。
3. 点「开始接收照片」，用手机浏览器扫码或手输**完整 URL**，选照片并上传。一次会话最多接收 8 张，每张传到 Pad 的 JPEG 最多 1 MiB。Pad 显示本次成功接收数；它不是整个项目的历史总数。二维码不可用时仍可手输，必要时在屏幕中滚动查看。
4. 点「停止接收并关闭」或离开页面；5 分钟到期、断网、项目标识变化或 SD 卡不可用也会终止接收。旧链接不应继续接收。停止不会删除此前成功的照片；中断时以**手机的成功回执和目录里的最终 JPEG**为准。
5. 再次打开「从手机加照片」即可查看该项目目录，不必另开会话。要取出照片，先停止接收，再用模拟 U 盘或读卡器打开对应 `metalio/e-ink/project/<id>/photos/`。这里没有相册解码、历史缩略图或自动改写 HTML 的功能；完整 App 应按同一标识引用该目录。请勿在接收中启用 U 盘、热拔卡或修改项目文件。

## 当前项目 → 同学：原有只读分享

把希望公开的单份 UTF-8 HTML 放到 `metalio/e-ink/project/current.html`（最多 64 KiB）。「设置 → 存储 → 分享当前项目卡」发送本次静态快照；不查项目照片目录，也不给别人写入权。卡缺失时不扫描全卡找替代。内联脚本、外链和交互式 HTML 不按原样保留；修改源文件不改变已分享快照。点「停止分享并关闭」立即撤销，离页或默认 5 分钟到期也会关闭。已下载的内容无法撤回。

三个入口都使用局域网 HTTP，持完整有效链接即可行使对应权限。不要公开截图或记录仍有效的地址。若同 SSID 仍不可达，先检查访客网/客户端隔离，不要为此打开无密码热点。

## 验证边界与上板清单

已用普通版固定提交的干净工作树验证 `--check` 不写入、实际安装、`git diff --check`、构建输入比对及拒绝重复安装。将安装后的界面源与主机端 LVGL/SD/服务替身编译后，实际调用页面回调验证了：开启前不监听、缺标识/确认前及列表启动中标识变更拒绝、上传计数刷新、运行中 ID 变化或 SD 失效撤销、二维码失败仍显示 URL、离页/到期及关闭清理。这不是原厂全量 ESP-IDF 编译，也没有刷机、实测墨水屏扫码或 SD 热拔。最低上板验收：

- 无标识、非法标识、模拟 U 盘占用、无 Wi-Fi：不得显示可用列表或上传 URL；不设置项目标识时，旧的单卡分享应仍可在 SD、Wi-Fi 正常时工作。
- 一个项目放 13 张不同归档卡，另一项目放 2 张，并让全局当前卡故意保留上一个项目的内容。检查扫码后只看到本项目、能翻页/点开/返回，拿旧 URL 在停止和切换后重试；空项目应能正常打开列表。另测上限、中文文件名、二维码失败手输、SD 丢失和低内存。
- 两个不同标识分别接收一张；核对手机成功回执、Pad 本次计数、各自目录内容。离开后重新打开只查目录不应开服务。
- 验证二维码、手输 URL、停止、待机/退出、超时、断网、卡丢失和旧地址重试；在部分上传时停止或切项目，不得在新项目落图。
- 验证 SD 满、空间不足和超限图片；观察内存水位、退出耗时及墨水屏刷新。收照片界面不解码图片、不扫描历史照片；仅在计数变化时更新计数标签。列表仅枚举本项目归档目录。LVGL 上的停止操作要等 HTTP 接收和当前 SD 操作退出，慢卡上可能短暂停顿。
